1. Basic Introduction to Embedded Platform

An embedded system is a small computer built into a device to do one dedicated job (washing machine, smart watch, car ECU). An embedded platform such as Arduino bundles a microcontroller, power circuit, USB interface and pin headers on one board so that students can build and test ideas quickly.

Key points

  • Microcontroller (MCU): a single chip with CPU, memory (Flash, SRAM, EEPROM) and I/O pins. Arduino Uno uses the ATmega328P.

  • Arduino Uno: 14 digital pins (6 PWM), 6 analog inputs, 16 MHz clock, 32 KB flash, 2 KB SRAM, operates at 5 V.

  • Two main functions: setup() runs once at start; loop() repeats forever.

Fig 1.1: Important parts of an Arduino Uno board

First program and pin functions

void setup() {

Serial.begin(9600); // start serial monitor

Serial.println("Hello, Embedded World!");

}

void loop() {

// runs again and again

}

Function Purpose
pinMode(pin, mode) Set a pin as INPUT, OUTPUT or INPUT_PULLUP
digitalWrite / digitalRead Write or read HIGH (5 V) / LOW (0 V)
analogRead(pin) Read 0-1023 from A0-A5
analogWrite(pin, v) PWM output, 0-255 (PWM pins only)
delay(ms) Pause the program for ms milliseconds

2. LED Blinking in Various Patterns

Blinking an LED is the "Hello World" of embedded systems. It teaches digital output, timing, and how to build patterns using loops and arrays.

Circuit basics

  • LED has two legs: anode (+, longer) and cathode (-, shorter).

  • Always use a current-limiting resistor (220 ohm to 330 ohm) in series: R = (Vsupply - Vled) / I = (5 - 2) / 0.015 = about 200 ohm.

  • Connect: Arduino pin -> resistor -> LED anode; LED cathode -> GND.

Fig 2.1: Timing diagram of three common LED patterns

Code: basic blink and a chaser

int leds[] = {2, 3, 4}; // LED pins

void setup() {

for (int i = 0; i < 3; i++) pinMode(leds[i], OUTPUT);

}

void loop() {

for (int i = 0; i < 3; i++) { // running pattern

digitalWrite(leds[i], HIGH);

delay(300);

digitalWrite(leds[i], LOW);

}

}

Pattern Idea
Blink / Alternate All LEDs ON and OFF together, or odd/even LEDs swapping
Chaser / Knight Rider Turn LEDs ON one by one using a for loop (forward and back)
Fade (PWM) analogWrite() from 0 to 255 to change brightness

Quick viva questions

  1. Why is a resistor needed with an LED?

  2. What is PWM and how does it dim an LED?

  3. How can an array shorten pattern code?
3. Analog Sensor Interfacing

The real world is analog (light, temperature, sound vary smoothly). A microcontroller works with digital numbers, so the Arduino's ADC (Analog to Digital Converter) converts a voltage between 0 and 5 V into a number between 0 and 1023 (10-bit).

Fig 3.1: LDR voltage divider and ADC conversion

Key points

  • Resolution: 5 V / 1024 = about 4.88 mV per step.

  • Formula: Voltage = analogRead(pin) x 5.0 / 1023.

  • Common analog sensors: LDR (light), LM35 (temperature, 10 mV per degree C), potentiometer, soil moisture, MQ gas sensors.

  • A sensor whose resistance changes is read through a voltage divider.

Code: LM35 temperature sensor on A0

void setup() { Serial.begin(9600); }

void loop() {

int raw = analogRead(A0);

float volt = raw * 5.0 / 1023.0;

float tempC = volt * 100.0; // LM35: 10 mV per C

Serial.print("Temp: "); Serial.println(tempC);

delay(500);

}

  1. What is the range of analogRead() on Arduino Uno?

  2. Why is a voltage divider used with an LDR?

  3. How can the resolution of an ADC be improved?
4. LCD and Bluetooth Interfacing with Platform

A 16x2 LCD shows 16 characters on each of 2 lines, giving the project a local display. HC-05 is a Bluetooth serial module that lets the Arduino exchange data wirelessly with a phone.

Fig 4.1: Arduino connected to a 16x2 LCD and HC-05 Bluetooth module

LCD key points

  • Uses the LiquidCrystal library in 4-bit mode: RS, E and D4-D7 pins.

  • A 10k pot on V0 sets contrast. Core commands: lcd.setCursor(col,row), print(), clear().

Bluetooth key points

  • HC-05 talks over UART serial (default 9600 baud in data mode, pairing PIN 1234 or 0000).

  • SoftwareSerial makes pins 8 and 9 an extra serial port, keeping USB free for debugging.

  • HC-05 RX accepts 3.3 V, so use a 1k/2k voltage divider on the Arduino TX line.

Code: show Bluetooth text on LCD

#include <LiquidCrystal.h>

#include <SoftwareSerial.h>

LiquidCrystal lcd(12, 11, 5, 4, 3, 2); // RS,E,D4,D5,D6,D7

SoftwareSerial bt(8, 9); // RX, TX

void setup() {

lcd.begin(16, 2);

bt.begin(9600);

lcd.print("BT Ready");

}

void loop() {

if (bt.available()) {

char c = bt.read();

lcd.clear();

lcd.print("Got: "); lcd.print(c);

}

}

  1. Why is the LCD used in 4-bit mode?

5. IR and Ultrasonic Sensor Integration

Distance and obstacle sensors are the eyes of robots and automatic systems. Two of the most common are the IR obstacle sensor and the HC-SR04 ultrasonic sensor.

Fig 5.1: Working principle of ultrasonic and IR sensors

Feature IR sensor Ultrasonic (HC-SR04)
Principle Reflected infrared light Time of flight of sound (40 kHz)
Range About 2 - 30 cm About 2 - 400 cm
Output Digital (LOW = obstacle) Pulse width on ECHO pin
Affected by Sunlight, black surfaces Soft/angled surfaces
Typical use Line follower, counter Distance meter, parking sensor

Code: ultrasonic distance

const int trig = 9, echo = 10;

void setup() {

pinMode(trig, OUTPUT); pinMode(echo, INPUT);

Serial.begin(9600);

}

void loop() {

digitalWrite(trig, LOW); delayMicroseconds(2);

digitalWrite(trig, HIGH); delayMicroseconds(10);

digitalWrite(trig, LOW);

long t = pulseIn(echo, HIGH); // microseconds

float cm = t * 0.034 / 2; // go and return

Serial.print(cm); Serial.println(" cm");

delay(300);

}

IR sensor: connect VCC, GND and OUT to a digital pin, then use digitalRead(pin). Output LOW means an obstacle is detected (on most modules).

Quick viva questions

  1. Why is the measured time divided by 2?

  2. Speed of sound is how many cm per microsecond?

  3. Where would you use IR instead of ultrasonic?
6. Basic of App Building

Mobile apps let us control hardware from a phone. Beginners use MIT App Inventor, a free block-based tool that needs no typing of code. It runs in the browser and creates an installable APK.

Fig 6.1: App Inventor - Designer, Blocks and APK

Steps to build an app

  • Designer: drag components (Button, Label, ListPicker, Slider, Clock) onto the screen.

  • Blocks: snap together event blocks (when Button1.Click) with action blocks (set Label.Text, call ...).

  • Test: use the MIT AI2 Companion app to preview live over Wi-Fi.

  • Build: Build > Android App (.apk) and install on the phone.

  • Concepts to know: event-driven programming, variables, UI components, and permissions (Bluetooth, Internet).

Quick viva questions

  1. What is an APK?

  2. What is event-driven programming?

  3. Name three components used in the Designer.
7. App Integration with Embedded Platform

Here the phone app and the Arduino exchange data over Bluetooth. The app sends commands (ON/OFF, speed) and the Arduino can send sensor values back for display.

Fig 7.1: Data flow between app and Arduino

How it works

  • In App Inventor add BluetoothClient and a ListPicker to select the paired HC-05.

  • Button click sends a character or number with Send1ByteNumber / SendText.

  • Arduino reads it with bt.read() and acts using if / switch statements.

  • Both sides must use the same baud rate (9600).

Code: control LED from phone

#include <SoftwareSerial.h>

SoftwareSerial bt(8, 9);

void setup() {

pinMode(13, OUTPUT);

bt.begin(9600);

}

void loop() {

if (bt.available()) {

char c = bt.read();

if (c == '1') digitalWrite(13, HIGH); // ON

if (c == '0') digitalWrite(13, LOW); // OFF

}

}

Quick viva questions

  1. What happens if the baud rates do not match?

  2. How can sensor values be shown in the app?

  3. Why pair the HC-05 before using the app?
8. Cloud Integration with App

IoT (Internet of Things) connects devices to the internet. Sensor data is sent to the cloud, stored, visualised, and accessed from anywhere through a mobile or web app.

Fig 8.1: IoT data path from sensor to dashboard

Platform Type Use
Blynk IoT app + cloud Drag-and-drop mobile dashboard for ESP32/ESP8266
ThingSpeak Cloud analytics Log sensor data and plot live graphs
Firebase Realtime database Store data and sync with a custom app

Key points

  • Arduino Uno has no Wi-Fi, so use ESP8266 / ESP32 (built-in Wi-Fi) or an ESP-01 module.

  • Typical steps: create account and channel/template, copy the API key / auth token, add credentials to code, upload and view data online.

  • Protocols: HTTP (REST) and MQTT (lightweight publish/subscribe).

  • Security: never share your API key publicly.

Quick viva questions

  1. What is IoT?

  2. Why use ESP32 instead of Arduino Uno here?

  3. Difference between HTTP and MQTT?
9. Basic of 3D Printing

3D printing (additive manufacturing) builds an object layer by layer from a digital model. The most common student printers use FDM (Fused Deposition Modelling), which melts plastic filament and deposits it through a nozzle.

Fig 9.1: Steps from idea to printed part

Term Meaning
Filament PLA (easy, biodegradable), ABS (strong, heat resistant), PETG (tough)
Nozzle / Hot-end Heats and extrudes plastic (PLA about 200 C)
Heated bed Keeps the first layer stuck to the plate (about 60 C for PLA)
Layer height Thickness of each layer, e.g. 0.2 mm; smaller = finer but slower
Infill Internal fill percentage; 15-20% for normal parts
Supports Temporary structures under overhangs
STL / G-code STL is the 3D model; G-code is the printer's step-by-step instructions

Where it helps in embedded projects

  • Print enclosures, sensor mounts, robot chassis and gears.

  • Free design tools: Tinkercad, Fusion 360. Slicers: Ultimaker Cura, PrusaSlicer.

Quick viva questions

  1. What is the role of a slicer?

  2. PLA vs ABS - which is easier to print and why?

  3. What are supports used for?
10. Project

The project combines everything learned: sensors, display, Bluetooth/app, cloud and a 3D-printed body. Choose a simple, useful problem and finish it end to end.

Fig 10.1: Step-by-step project cycle

Sample project ideas

Project Main components

Bluetooth car HC-05, motor driver L298N, 2 DC motors, app
Weather monitor DHT11, LCD, ESP32, ThingSpeak
Automatic street light LDR, relay, LED

Tips

  • Draw a block diagram and a circuit diagram first; test each module separately, then combine.

  • Keep a log: components list, pin table, code with comments, photos of the circuit.

  • Report sections: Aim, Components, Block diagram, Circuit, Code, Working, Output, Conclusion, Future scope.

Self-check before demo

  1. Does every module work alone?

  2. Is the wiring neat and labelled?

  3. Can you explain every line of your code?
11. Seminar / Presentation

The last session is to present your project. A clear story matters as much as the working model.

Fig 11.1: Recommended flow of the presentation

Do's

  • One idea per slide, large readable text, more pictures and diagrams than paragraphs.

  • Show a live demo or a short video as backup.

  • Practise to finish in the given time (about 5-8 minutes) and speak to the audience, not the screen.

Expected questions

  • Why did you choose this component or sensor?

  • What problem does it solve and how could it be improved?

  • What was the biggest difficulty and how did you fix it?

Final checklist

  1. Slides saved on pen drive and email.

  2. Hardware, cables and power supply packed.

  3. Team roles decided: who explains what.
